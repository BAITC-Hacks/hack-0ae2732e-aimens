# План доведения MVP AI Sana до сдачи

## Точка старта (23 сентября 2026)

Сквозной путь уже есть в коде: описание → вопросы → редактируемая карточка → подтверждение и рейтинг → каталог → предложение → ручной выбор → первый результат → подтверждение и 10 баллов. Это подтверждают текущие проверки: `npm test` — 28/28, `npm run test:e2e` — 3/3 с Edge, `npm run lint`, `npm run typecheck` и `npm run build` — успешно. Реальный запрос к OpenAI с ключом не проверялся; локальный режим работает. Это план оставшейся работы, а не план повторной разработки готовых модулей.

Кейс AI Sana и локальные «Правила оценивания.docx» содержат разные шкалы: рейтинг **карточки** 0–100 внутри продукта и оценку **проекта** жюри. Их нельзя смешивать. Организационные материалы HackAlem также расходятся с кейсом по размеру команды; для официальной сдачи нужны действующие условия конкретного мероприятия.

## Порядок работы

### Шаг 1. Сверить сдачу с официальными условиями

**Задача.** Зафиксировать выданный организатором репозиторий, допустимость текущей предварительной разработки, состав команды, дедлайн и формат сдачи. Не переносить заранее созданный код, если правила этого запрещают.

**Готово, когда:** есть запись о применяемых условиях и расхождениях в `docs/progress.md` или `docs/task.md`; в README указана только подтверждённая история разработки и сдачи.

**Проверка:** сравнить запись с опубликованными инструкциями организатора; проверить `git remote -v` и историю коммитов. **Зависимости:** нет. **Файлы:** `docs/progress.md`, `docs/task.md`, при необходимости `README.md`. **Оценка:** 15–30 минут, зависит от доступности официальных правил.

### Шаг 2. Довести пять исходных черновиков до формата ТЗ

**Задача.** Добавить каждому из пяти примеров собственную тему/отрасль и явно разную полноту сведений; при выборе примера переносить в форму и текст, и тему. Сохранить синтетический характер данных и идемпотентность инициализации.

**Готово, когда:** пять примеров имеют текст и отрасль; выбор «Маршруты курьеров» задаёт логистику, а не тему по умолчанию; существующие пять опубликованных карточек, пять команд и пять предложений не дублируются после перезапуска.

**Проверка:** тест данных/формы, повторный запуск с той же SQLite. **Зависимости:** нет. **Файлы:** `src/domain/demo-data.ts`, `src/components/task-editor.tsx`, соответствующий тест. **Оценка:** 20–40 минут.

### Шаг 3. Закрыть непроверенные границы сквозного пути

**Задача.** Существующие unit-тесты уже проверяют две выбранные команды, повторное подтверждение без двойных баллов и публикацию с низким рейтингом. Добавить недостающую связку: отклик на только что опубликованную задачу с низким рейтингом. Проверить сохранение вводимого текста при ошибке AI или транспорта в браузере. При ручном проходе убедиться, что второй выбор не меняет статус остальных предложений.

**Готово, когда:** тест доказывает публикацию и отклик на одну и ту же задачу с низким рейтингом; при ошибке анализа введённое описание остаётся в форме, а режим/ошибка названы пользователю; ранее существовавшие проверки множественного выбора и баллов продолжают проходить.

**Проверка:** `npm test`, `npm run test:e2e`. **Зависимости:** шаг 2 для теста выбора примера. **Файлы:** `tests/store.test.ts`, `tests/e2e/demo.spec.ts`, при найденном дефекте — только соответствующий модуль. **Оценка:** 40–70 минут.

### Шаг 4. Пройти доступность и ошибки руками

**Задача.** По `design.md` проверить клавиатурой все основные действия; ширины 320 и 390 px, увеличение 200%, длинный текст/URL, пустой фильтр, отказ сервера и отсутствие API-ключа. Исправлять только воспроизводимые дефекты основного пути.

**Готово, когда:** публикация, отклик, выбор и подтверждение доступны без мыши; фокус видим; статус и рейтинг понятны без цвета; нет горизонтальной прокрутки и потери введённых данных.

**Проверка:** ручной браузерный проход и точечные Playwright-проверки для найденных дефектов. **Зависимости:** шаг 3. **Файлы:** `src/components/`, `src/app/`, `tests/e2e/demo.spec.ts` по фактическим находкам. **Оценка:** 30–60 минут.

### Шаг 5. Проверить воспроизводимость как эксперт

**Задача.** В чистой копии проекта с Node 24.x выполнить `npm ci`, `npm run build`, `npm test`, `npm run test:e2e`, `npm run lint` и `npm run typecheck`. Запустить собранную версию без ключа, создать запись, перезапустить процесс и убедиться, что задача, отклик и баллы сохранились. Проверить, что `.env.local` и файл SQLite не входят в Git.

**Готово, когда:** все команды действительно проходят в чистой копии; запуск по README повторяем без личного аккаунта и ключа; сохранность подтверждена после перезапуска процесса, а не только класса Store в тесте.

**Проверка:** журнал команд и короткая запись результатов в `docs/progress.md`; `git status --short`. **Зависимости:** шаги 2–4. **Файлы:** `README.md`, `docs/progress.md`, при необходимости конфигурация. **Оценка:** 40–60 минут.

### Шаг 6. Провести пятиминутную репетицию защиты

**Задача.** Пройти один живой пример со списанием выпечки из `docs/demo.md`: слабое описание, минимум три вопроса, рост рейтинга, публикация, предложение команды, ручной выбор, первый результат и +10 после подтверждения. Засечь время и убрать лишние переходы из сценария показа.

**Готово, когда:** весь путь укладывается в пять минут без ручного изменения базы или имитации слайдами; README и `docs/demo.md` совпадают с реальными названиями кнопок и поведением.

**Проверка:** повторить на свежей временной SQLite и записать фактическую длительность. **Зависимости:** шаг 5. **Файлы:** `docs/demo.md`, `README.md`. **Оценка:** 20–30 минут.

## Контрольные точки и приоритет

1. **После шагов 2–3:** основной путь и спорные правила продукта подтверждены тестами. Если найден дефект, исправить его до визуальной полировки.
2. **После шага 4:** сценарий доступен на ноутбуке и узком экране, ошибки не уничтожают ввод.
3. **После шагов 5–6:** чистый запуск, постоянная база, документация и показ проверены фактически.

Если времени мало, порядок: шаг 1 → шаг 2 → шаг 3 → шаг 5 → шаг 6; шаг 4 сократить до клавиатурного прохода и 320 px. Не добавлять регистрацию, чат, рекомендации, файлы или новую инфраструктуру.

## Основные риски

| Риск | Действие |
| --- | --- |
| Условия организатора отличаются от локальных материалов | Выполнить шаг 1 до изменения состава сдачи или переноса кода |
| Примеры черновиков выглядят как нужный набор данных, но не содержат отрасль | Исправить структуру примеров и перенос темы в форме |
| Платный AI недоступен на защите | Показывать явно подписанный локальный режим и проверенный полный путь без ключа |
| Тест Store не доказывает перезапуск процесса | Выполнить отдельную проверку шага 5 |
| Демо длится больше пяти минут | Репетировать один пример и сохранить готовый маршрут в `docs/demo.md` |
