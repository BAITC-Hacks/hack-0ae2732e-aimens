# SanaLink — реальные задачи, сильные команды

SanaLink соединяет бизнес и студенческие команды. Бизнес описывает потребность, отвечает на вопросы помощника, проверяет карточку и публикует задачу. Команды предлагают решения, бизнес вручную выбирает одну или несколько команд. Подтверждённый первый результат приносит команде **10 баллов**.

Проект команды **Aimens** по кейсу AI Sana / HackAlem. [Репозиторий](https://github.com/BAITC-Hacks/hack-0ae2732e-aimens). Это запускаемое локальное демо: регистрация и API-ключ не нужны, данные синтетические.

## Быстрый запуск

Требуются **Node.js 24.x** и npm; поле `packageManager` фиксирует npm 11.17.0. SQLite встроена в Node.js, отдельный сервер базы не нужен.

```sh
npm ci
npm run dev
```

Откройте [http://127.0.0.1:3000](http://127.0.0.1:3000). После установки зависимостей демо работает без интернета. Шрифты, SVG и PNG находятся в проекте. Скрипты установки зависимостей отключены в `.npmrc`.

Для production-сборки:

```sh
npm run build
npm start
```

Рабочая база `data/praktika.sqlite` создаётся автоматически. Повторная инициализация добавляет отсутствующие демозаписи и сохраняет пользовательские задачи, предложения, решения и баллы. Второй сервер можно запустить на другом порту: `npm run dev -- --port 3001`.

## Страницы и действия

| Маршрут            | Что работает                                                                                       |
| ------------------ | -------------------------------------------------------------------------------------------------- |
| `/`                | Главная с поиском, категориями, актуальными задачами и объяснением сценария                        |
| `/catalog`         | Полный каталог, текстовый поиск, фильтры по теме, готовности и формату, сортировка и избранное     |
| `/tasks/new`       | Четыре шага: черновик → уточнение → карточка → публикация                                          |
| `/tasks/[id]`      | Детали и рейтинг; предложение команды; сравнение, выбор и отклонение предложений; первый результат |
| `/tasks/[id]/edit` | Изменение карточки с предварительным рейтингом и повторным подтверждением                          |
| `/business`        | Задачи бизнеса, предложения команд, решения и подтверждение результатов                            |
| `/team`            | Отклики текущей команды, статусы, отправка первого результата и баллы                              |
| `/teams`           | Команды с символами, навыками и интересами; здесь же можно создать свою команду                    |
| `/teams/new`       | Отдельный сценарий: имя команды, направления и один из десяти казахских символов                   |
| `/guide`           | Правила платформы и формула готовности                                                             |

В меню профиля справа выберите «Бизнес» или существующую команду. Создание команды вынесено отдельно в `/teams/new`; новый профиль сразу становится активным. Выбранный профиль сохраняется на время вкладки.

Избранное сохраняется в `localStorage` отдельно для каждого демопрофиля. Оно остаётся после перезагрузки браузера; при недоступном хранилище работает в памяти. Подборка для команды объясняет совпадения темы и навыков. Все опубликованные задачи остаются доступны каждой команде.

## Демонстрация за пять минут

1. В режиме бизнеса нажмите **«Разместить задачу»**, выберите пример кофейни и **«Помочь с описанием»**. Без ключа помощник явно подписан как локальный.
2. Если тема непонятна, нажмите **«Не знаю тему — определить по описанию»**. Ответьте на вопросы и нажмите **«Перейти к карточке»**. Дополните данные со способом доступа, результат и показатель с целевым значением. Предварительный рейтинг обновится.
3. Откройте **«Предпросмотр»**, нажмите **«Анализ задачи и финальная оценка»**, проверьте объяснения, отметьте достоверность сведений, подтвердите карточку и опубликуйте. Для публикации доступен любой рейтинг.
4. В меню профиля выберите **Qyran Lab**, откройте задачу и отправьте идею, план, срок и ссылку `https://example.com/prototype`.
5. Вернитесь в «Бизнес», рассмотрите предложение и вручную выберите команду. При нескольких предложениях доступна таблица сравнения. В режиме Qyran Lab отправьте описание первого результата и `https://example.com/result`.
6. В режиме бизнеса подтвердите результат. В кабинете команды появятся **10 баллов**; повторное подтверждение этой пары «задача — команда» новых баллов не даёт.

[Подробный сценарий и готовые ответы](docs/DEMO.md).

## Рейтинг и правила работы

Предварительный `computeReadiness(card)` в `src/domain/task.ts` показывает заполненность по фиксированной шкале. Перед публикацией отдельный API-анализ оценивает полезность конкретики для команды по тем же критериям и тем же максимальным весам. Объяснения, баллы и итоговая оценка сохраняются с задачей; это не оценка бизнеса и не проверка истинности сведений.

| Подтверждённые сведения                          |   Баллы |
| ------------------------------------------------ | ------: |
| Контекст                                         |      10 |
| Потребность                                      |      10 |
| Данные **вместе со способом доступа**            |      20 |
| Ожидаемый результат                              |      15 |
| Показатель успеха **вместе с целевым значением** |      15 |
| Ограничения                                      |      10 |
| Пользователи                                     |      10 |
| Контакт                                          |       5 |
| Формат взаимодействия с бизнесом                 |       5 |
| **Всего**                                        | **100** |

Уровни: **0–39 «Черновик», 40–69 «Рабочая», 70–89 «Готовая», 90–100 «Приоритетная»**. Предварительная шкала присуждает полный вес или 0 и отсеивает короткие ответы-заполнители; финальная оценка выставляет баллы внутри каждой неизменной границы. Название, тема, `workFormat` и `skills` не добавляют баллы. `workFormat` описывает место работы, а `interaction` — консультации бизнеса.

- До ручного подтверждения рейтинг в редакторе предварительный. Сохранённый неподтверждённый черновик имеет официальный рейтинг 0. Публичная карточка обновляется вместе с подтверждёнными полями.
- Для публикации нужны название, тема и явное подтверждение. Низкий рейтинг не препятствует публикации и откликам.
- Порядок каталога по умолчанию: рейтинг по убыванию → более ранняя публикация → идентификатор. Можно выбрать сначала новые или сначала старые задачи. Фильтры и сортировка меняют представление.
- Предложений может быть сколько угодно. Статусы: `pending`, `selected`, `rejected`. Выбор одной команды не отклоняет остальные; можно выбрать несколько команд.
- Отклик и выбор команды дают 0 баллов. Только подтверждение первого результата бизнесом даёт **10 баллов один раз для пары «задача — команда»**, даже при нескольких предложениях одной команды.
- Готовность показывает полноту задачи. Формула не проверяет истинность текста, репутацию компании или качество обещанного решения.

## AI и локальный режим

Без ключа помощник определяет недостающие поля, задаёт пять вопросов и локально предлагает тему и оценку. Для уже заполненных полей он предлагает уточнение. Ответы остаются редактируемыми; готовые факты не выдумываются. Перед публикацией кнопка анализа запускает финальную оценку; при настроенном ключе применяется структурированный AI-разбор, иначе показывается локальная оценка.

Для OpenAI скопируйте `.env.example` в `.env.local`, укажите серверный ключ и перезапустите приложение:

| Переменная       | Значение по умолчанию                                    |
| ---------------- | -------------------------------------------------------- |
| `AI_MODE`        | `auto`; `local` принудительно включает локальные вопросы |
| `OPENAI_API_KEY` | Пусто; без ключа работает локальный режим                |
| `OPENAI_MODEL`   | `gpt-4.1-mini-2025-04-14`                                |
| `DATABASE_PATH`  | `data/praktika.sqlite`                                   |

Сервер использует Responses API, Structured Outputs, тайм-аут 20 секунд, `maxRetries: 0` и `store: false`. Извлечённые значения принимаются только при проверенном дословном совпадении с фрагментом текста пользователя и только в пустые поля. Повторяющиеся вопросы заменяются неповторяющимися локальными. Некорректный ответ, отказ или ошибка API включают явно обозначенный локальный режим. Ошибка запроса сохраняет текущий ввод в форме. Перед внешним анализом форма предупреждает о передаче текста; сервер ограничивает тело POST 65 000 байтами и AI-анализ 20 запросами в минуту на клиента в памяти процесса.

Ключ находится только в серверном окружении. AI не публикует задачи и не выбирает команды. [Промпт, схемы, резерв и примеры](docs/AI_PROMPT.md). Реальный платный запрос в рамках этой доработки не выполнялся; автоматические тесты адаптера подменяют SDK.

## Стек и структура

Сохранён существующий стек: **Next.js App Router, React, TypeScript, Tailwind CSS, Zod и SQLite через `node:sqlite`**. Один Node.js процесс, без ORM. Vitest проверяет правила и серверные операции; Playwright — сценарии в браузере. Локальный шрифт DM Sans, Lucide для вспомогательных иконок, собственные SVG для бренда и иллюстраций. Sharp экспортирует PNG.

```text
src/
  app/                   страницы, HTTP-обработчики, общие стили и токены
  components/            оболочка, каталог, рейтинг, избранное, предложения
    task-builder/        шаги конструктора и состояние редактирования
  domain/                типы, Zod, рейтинг, каталог, рекомендации, демоданные
  server/                SQLite, операции и адаптер AI
  assets/svg/            оригиналы 30 векторных изображений
public/assets/
  svg/                   копии SVG для браузера
  png/                   PNG 1×/2× и hero-preview.png
scripts/export-assets.mjs экспорт и проверка векторных источников
tests/                   Vitest и e2e Playwright
docs/                    архитектура, дизайн, AI и сценарий показа
```

[Архитектура и HTTP-контракт](docs/ARCHITECTURE.md) · [Дизайн-система](docs/DESIGN_SYSTEM.md).

## SVG и воспроизводимый экспорт PNG

```sh
npm run assets:export
```

Скрипт читает все `.svg` из `src/assets/svg/`, проверяет `viewBox` и отсутствие встроенного растра/внешних изображений, копирует SVG в `public/assets/svg/` и экспортирует каждый через Sharp в `public/assets/png/<имя>@1x.png` и `<имя>@2x.png`. Для hero дополнительно создаётся `hero-preview.png` на светлом фоне. Иконки имеют базовый размер 24×24, логомарк — 40×40, hero — 680×490. Перед экспортом цвет `currentColor` заменяется на брендовый тёмный `#16332f`.

В набор входят логотип, логомарк, навигация, действия, шесть категорий, пустое состояние и редакционная иллюстрация бизнеса со студентами. Все изображения локальные. Изображения из внешних сервисов и hotlinking не используются.

## Проверки и воспроизводимость

Команды для проверки текущей версии:

```sh
npm ci
npm run assets:export
npm run typecheck
npm run lint
npm test
npx playwright install chromium
npm run test:e2e
npm run build
```

Проверено 23 сентября 2026 года на Node.js 24.18.0: чистая установка `npm ci` и экспорт ресурсов прошли для SanaLink до объединения веток. На объединённой версии прошли production-сборка, lint, typecheck, **58 модульных и 12 браузерных тестов**. E2E запускались в установленном Microsoft Edge. Отдельно до объединения проверен реальный перезапуск production-процесса с той же SQLite: задача, предложение, выбор и результат сохранились; повторное подтверждение оставило 10 баллов. Платный OpenAI-запрос в объединённой версии не выполнялся.

Playwright запускает отдельный сервер на **3100**, использует локальный AI и отдельную временную SQLite. Рабочая база не затрагивается. Если вместо Chromium нужен установленный Edge, в PowerShell:

```powershell
$env:PLAYWRIGHT_CHANNEL = 'msedge'
npm run test:e2e
```

Для проверки перезапуска сохраните задачу, запомните её URL, остановите сервер и снова выполните `npm start` после сборки. Откройте тот же URL: карточка, предложения и подтверждённые результаты должны сохраниться. Проверка всего пути и критерии результата описаны в [DEMO.md](docs/DEMO.md).

## Демоданные и ограничения

При первой инициализации доступны пять исходных примеров, пять опубликованных карточек с рейтингами **100 / 90 / 75 / 55 / 20**, пять команд и пять предложений. Прототипы и контакты используют демонстрационные адреса `example.com`. Они не представляют реальные компании или готовые решения.

Один демобизнес управляет всеми задачами. `x-demo-actor` моделирует роль, но не является аутентификацией. Профиль восстанавливается после перезагрузки в той же вкладке; несохранённый редактор сбрасывается. Сохранённые данные остаются в SQLite, избранное — в браузере. Выбор/отклонение предложения окончательны для этого предложения; подтверждённый первый результат не редактируется.

Подборки основаны на точных совпадениях темы и навыков и объясняют совпадения. Чата, уведомлений, загрузки файлов, календаря и production-инфраструктуры нет. SQLite рассчитана на один локальный сервер.
