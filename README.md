# Практика — задачи бизнеса для студенческих команд

Проект команды **Aimens**. Репозиторий: [BAITC-Hacks/hack-0ae2732e-aimens](https://github.com/BAITC-Hacks/hack-0ae2732e-aimens).

Локальное демо по кейсу AI Sana: бизнес превращает потребность в понятную карточку, подтверждает сведения, публикует задачу и выбирает команды среди откликнувшихся. Команда получает **10 баллов** после подтверждения первого результата.

**Без регистрации, аккаунтов и обязательного API-ключа.** В правом верхнем углу переключаются бизнес и пять студенческих команд. Все начальные данные синтетические.

## Быстрый запуск

Требуются **Node.js 24.x** и npm. Проверено на Windows с Node 24.18.0 и npm 11.17.0. SQLite встроена в Node; отдельный сервер базы не нужен.

```sh
npm ci
npm run dev
```

Откройте [http://127.0.0.1:3000](http://127.0.0.1:3000). База `data/praktika.sqlite` создаётся автоматически. Начальные записи добавляются один раз; повторный запуск сохраняет пользовательские задачи, решения и баллы. Скрипты зависимостей отключены в `.npmrc`; текущий набор пакетов работает с этой настройкой.

Сборка и запуск собранной версии:

```sh
npm run build
npm start
```

Не запускайте две копии приложения на одном порту. Для другого порта: `npm run dev -- --port 3001`.

### Демосценарий за пять минут

1. В режиме бизнеса нажмите **«Предложить задачу»**. Выберите пример кофейни или введите свою потребность.
2. Нажмите **«Помочь с описанием»**, проверьте подпись режима, источники предложений AI и ответьте на вопросы. Без ключа показывается режим локальных правил.
3. Дополните название, данные и доступ, результат и критерий успеха. Покажите три ближайших шага и расстояние до следующего уровня. Отметьте подтверждение и опубликуйте.
4. Переключитесь на **Nomad Labs**. На карточке отправьте идею, план, срок и ссылку `https://example.com/prototype`.
5. Вернитесь в **Бизнес** и выберите команду. Затем снова переключитесь на Nomad Labs и отправьте описание первого результата со ссылкой `https://example.com/result`.
6. В режиме бизнеса подтвердите результат. В «Моих откликах» команды появятся **10 баллов**.

Подробная репетиция: [docs/demo.md](docs/demo.md).

## Правила рейтинга и каталога

Одна функция `computeReadiness(card)` используется интерфейсом и сервером. **AI баллы не начисляет.**

| Подтверждённые сведения           | Баллы |
| --------------------------------- | ----: |
| Текущая ситуация                  |    10 |
| Потребность бизнеса               |    10 |
| Материалы **и** способ доступа    |    20 |
| Ожидаемый результат               |    15 |
| Показатель **и** целевое значение |    15 |
| Ограничения                       |    10 |
| Пользователи                      |    10 |
| Контакт                           |     5 |
| Взаимодействие                    |     5 |

Уровни: **0–39 черновик, 40–69 рабочая, 70–89 готовая, 90–100 приоритетная**. Критерии и веса фиксированы. Поле считается заполненным, только если после нормализации в нём есть хотя бы одна буква или цифра: пробелы, пунктуация и оформление сами по себе дают 0. Короткие осмысленные ответы вроде «AI» или «2%» засчитываются. Для данных точные варианты «нет данных», «данные отсутствуют», «не указано», «не уточнено» и аналогичные формулировки отсутствия дают 0; для 20 баллов нужны и описание данных, и выбранный способ доступа. Значение цели — текст, например «не более 2 минут».

- Публикация независима от рейтинга: нужны название, тема и ручное подтверждение. Даже задачу с 0 баллов можно опубликовать и принять на неё отклики.
- Неподтверждённая задача в каталог не попадает. Несохранённые изменения существуют в форме; публичная карточка и рейтинг меняются вместе после подтверждённого сохранения.
- Порядок каталога: рейтинг по убыванию → более ранняя публикация → идентификатор. Каталог одинаков для всех команд.
- Число предложений не ограничено. Бизнес выбирает ноль, одну или несколько команд. Другие предложения не отклоняются автоматически.
- За отклик и выбор команды баллы не начисляются. Первый результат доступен выбранной команде. Награда **10 баллов один раз на пару «задача — команда»**, включая повторные запросы подтверждения.
- Рейтинг показывает полноту сведений; истинность данных и реализуемость обещаний не проверяются.

Панель рейтинга показывает до трёх самых весомых незаполненных критериев с возможной прибавкой и расстояние до следующего уровня. Это подсказка по заполнению той же формулы, а не отдельная игровая валюта.

## AI и резервный режим

Без настройки используется локальный помощник: он выбирает вопросы по незаполненным полям, а для заполненных предлагает конкретизацию. Исходный текст сохраняется в контексте, ответы можно редактировать. Локальный режим не имитирует обращение к модели.

Для OpenAI скопируйте `.env.example` в `.env.local`, задайте `OPENAI_API_KEY` и оставьте `AI_MODE=auto`. Перезапустите сервер. Ключ читается только сервером.

| Переменная       | Значение по умолчанию                                    |
| ---------------- | -------------------------------------------------------- |
| `AI_MODE`        | `auto`; `local` принудительно включает локальные вопросы |
| `OPENAI_API_KEY` | Пусто; без ключа работает локальный режим                |
| `OPENAI_MODEL`   | `gpt-4.1-mini-2025-04-14`                                |
| `DATABASE_PATH`  | `data/praktika.sqlite`                                   |

Интеграция использует Responses API, Structured Outputs, тайм-аут 20 секунд, без повторов и с `store: false`. Извлечённые значения принимаются только при совпадении с фрагментом пользовательского текста. Интерфейс явно показывает режим OpenAI или локальные правила и выводит проверенную цитату рядом с предложенным полем, пока пользователь не изменил это значение. Существующие ответы не перезаписываются.

Сервер удаляет повторяющиеся вопросы по полю и нормализованному тексту и дополняет ответ до 3–5 вопросов. Вопрос про данные также уточняет способ доступа; на следующем шаге он выбирается отдельным полем. Перед отправкой интерфейс предупреждает не указывать пароли, ключи и персональные данные. JSON-тело ограничено 65 000 байт: сервер читает поток частями и прекращает чтение при превышении. `/api/analyze` дополнительно ограничивает одного клиента 20 запросами в минуту в памяти текущего процесса; при превышении возвращаются 413 или 429 с `Retry-After`. Неверный формат, отказ, ошибка или тайм-аут переводят запрос в явно обозначенный резервный режим. AI не публикует карточку и не выбирает команды.

[AI-контракт, промпт и примеры](docs/ai.md). Live smoke через локальный `/api/analyze` выполнен с настроенным OpenAI API: сервер вернул режим `openai`, четыре уникальных вопроса и три предложения с тремя проверенными источниками. Локальный режим, обработка модельного ответа и ошибки адаптера дополнительно проверены тестами без сетевых запросов.

## Архитектура

```text
src/
  app/           страницы Next.js и HTTP-обработчики
  components/    формы, оболочка, рейтинг, предложения, демоконтекст
  domain/        общие типы, Zod, рейтинг, синтетические данные
  server/        SQLite, серверные операции и OpenAI
 tests/
  *.test.ts      правила, операции, сохранность данных, AI
  e2e/           сценарий Playwright и проверка страниц
 docs/           архитектура, AI, сценарий показа и прогресс
```

Next.js App Router + React + TypeScript; Tailwind CSS и обычные стили; Zod; SQLite через `node:sqlite`, без ORM. Один локальный процесс. Рейтинг пересчитывается сервером; баллы команды вычисляются по подтверждённым этапам. [Подробнее](docs/architecture.md).

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npx playwright install chromium
npm run test:e2e
npm run build
```

Playwright запускает отдельное приложение на порту **3100**, принудительно включает локальный AI и создаёт отдельную временную SQLite. Рабочая база не используется. Тест покрывает создание → вопросы → 100 баллов → публикацию → несохранённые изменения → отклик → выбор → результат → подтверждение → 10 баллов. Второй сценарий проверяет страницы, фильтры и доступ команды к задаче с 20 баллами.

Вместо загрузки Chromium можно использовать установленный Edge. В PowerShell:

```powershell
$env:PLAYWRIGHT_CHANNEL = 'msedge'
npm run test:e2e
```

## Начальные данные и ограничения демо

Пять исходных примеров, пять опубликованных карточек с рейтингами **100 / 90 / 75 / 55 / 20**, пять команд и пять предложений. Прототипы в начальных данных ведут на `example.com` и не являются действующими решениями. Все компании, контакты, команды и описания вымышлены.

Один демобизнес управляет всеми задачами. Выбранный профиль сохраняется в `sessionStorage` вкладки и после обновления восстанавливается только из допустимого списка `business`, `team-1`…`team-5`; неизвестное значение удаляется. Заголовок `x-demo-actor` и это клиентское хранение демонстрируют сценарий, но не являются аутентификацией или границей доступа. Несохранённая форма при обновлении сбрасывается. Завершённое решение по предложению не отменяется в интерфейсе. Подтверждённый результат не редактируется.

На странице команды четыре этапа показывают путь «предложение → выбор → первый результат → подтверждение и +10». Общий список команд сортируется по подтверждённым баллам; при равенстве команды делят место. Повторные предложения по одной задаче разрешены как независимые варианты и не дают дополнительных баллов сами по себе.

Нет регистрации, чата, уведомлений, загрузки файлов, рекомендаций и инфраструктуры публичного размещения. SQLite рассчитана на один локальный сервер. Этот прототип нужно адаптировать перед реальной многопользовательской эксплуатацией.
