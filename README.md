# SanaLink — рейтинг готовности бизнес-задач и открытый выбор команд

SanaLink соединяет бизнес и студенческие команды. Бизнес описывает потребность, отвечает на вопросы помощника, проверяет карточку и публикует задачу. Команды предлагают решения, бизнес вручную выбирает одну или несколько команд. Подтверждённый первый результат приносит команде **10 баллов**.

Проект команды **Aimens** по кейсу AI Sana / HackAlem. [Репозиторий](https://github.com/BAITC-Hacks/hack-0ae2732e-aimens). Это запускаемое локальное демо: регистрация и API-ключ не нужны, данные синтетические.

## Быстрый запуск

Требуются **Node.js 24.x** и npm; поле `packageManager` фиксирует npm 11.17.0. SQLite встроена в Node.js, отдельный сервер базы не нужен.

```sh
git clone https://github.com/BAITC-Hacks/hack-0ae2732e-aimens.git
cd hack-0ae2732e-aimens
npm ci
npm run dev
```

Откройте [http://127.0.0.1:3000](http://127.0.0.1:3000). После установки зависимостей демо работает без интернета. Шрифты, SVG и PNG находятся в проекте. Скрипты установки зависимостей отключены в `.npmrc`.

Для production-сборки:

```sh
npm run build
npm start
```

Рабочая база `data/praktika.sqlite` создаётся автоматически. Повторная инициализация добавляет отсутствующие демозаписи и сохраняет пользовательские задачи, предложения, решения и баллы. Второй сервер можно запустить на другом порту: `npm run dev -- --port 3001`.

## Страницы и действия

| Маршрут | Что работает |
| --- | --- |
| `/` | Главная с поиском, категориями, актуальными задачами и объяснением сценария |
| `/catalog` | Полный каталог, текстовый поиск, фильтры по теме, готовности и формату, сортировка и избранное |
| `/tasks/new` | Четыре шага: черновик → уточнение → карточка → публикация |
| `/tasks/[id]` | Детали и рейтинг; предложение команды; сравнение, выбор и отклонение предложений; первый результат |
| `/tasks/[id]/edit` | Изменение карточки с предварительным рейтингом и повторным подтверждением |
| `/business` | Задачи бизнеса, предложения команд, решения и подтверждение результатов |
| `/team` | Отклики текущей команды, статусы, отправка первого результата и баллы |
| `/teams` | Пять студенческих команд с навыками, интересами и демопрофилями |
| `/guide` | Правила платформы и формула готовности |

Под шапкой доступен переключатель **«Бизнес / Студент»** и прямой переход в кабинет. Конкретную команду можно выбрать в меню профиля справа (**«Демопрофиль»**). При возврате в студенческий режим переключатель помнит последнюю выбранную команду до перезагрузки; сам демопрофиль сохраняется на время вкладки.

В конструкторе можно возвращаться к уже посещённым шагам без повторного AI-запроса. Изменения по-прежнему сбрасывают подтверждение. До подтверждения бизнесом команда может **исправить первый результат**: текст и ссылку; баллы начисляются только после подтверждения.

Избранное сохраняется в `localStorage` отдельно для каждого демопрофиля. Оно остаётся после перезагрузки браузера; при недоступном хранилище работает в памяти. Подборка для команды объясняет совпадения темы и навыков. Все опубликованные задачи остаются доступны каждой команде.

## Демонстрация за пять минут

1. В режиме бизнеса нажмите **«Разместить задачу»**, выберите пример кофейни и **«Помочь с описанием»**. Без ключа помощник явно подписан как локальный.
2. Ответьте на вопросы и нажмите **«Перейти к карточке»**. Дополните данные со способом доступа, результат и показатель с целевым значением. Покажите изменение предварительного рейтинга.
3. Откройте **«Предпросмотр»**, отметьте, что сведения проверены, нажмите **«Подтвердить карточку»**, затем **«Опубликовать задачу»**. Найдите её в каталоге.
4. В меню профиля выберите **Nomad Labs**, откройте задачу и отправьте идею, план, срок и ссылку `https://example.com/prototype`.
5. Вернитесь в «Бизнес», рассмотрите предложение и вручную выберите команду. При нескольких предложениях доступна таблица сравнения. В режиме Nomad Labs отправьте описание первого результата и `https://example.com/result`.
6. В режиме бизнеса подтвердите результат. В кабинете команды появятся **10 баллов**; повторное подтверждение этой пары «задача — команда» новых баллов не даёт.

[Подробный сценарий и готовые ответы](docs/DEMO.md).

## Рейтинг и правила работы

`computeReadiness(card)` в `src/domain/task.ts` — единая чистая функция для интерфейса и серверного пересчёта. Клиент не отправляет готовый рейтинг как источник истины. AI баллы не начисляет.

| Подтверждённые сведения | Баллы |
| --- | ---: |
| Контекст | 10 |
| Потребность | 10 |
| Данные **вместе со способом доступа** | 20 |
| Ожидаемый результат | 15 |
| Показатель успеха **вместе с целевым значением** | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Контакт | 5 |
| Формат взаимодействия с бизнесом | 5 |
| **Всего** | **100** |

Уровни: **0–39 «Черновик», 40–69 «Рабочая», 70–89 «Готовая», 90–100 «Приоритетная»**. Каждая строка даёт полный вес или 0. Пробелы и пунктуация не считаются заполнением; точные фразы об отсутствии данных и отсутствие способа доступа дают 0 за данные. Название, тема, `workFormat` и `skills` не добавляют баллы. `workFormat` описывает место работы, а `interaction` — консультации бизнеса.

- До ручного подтверждения рейтинг в редакторе предварительный. Сохранённый неподтверждённый черновик имеет официальный рейтинг 0. Публичная карточка обновляется вместе с подтверждёнными полями.
- Для публикации нужны название, тема и явное подтверждение. Низкий рейтинг не препятствует публикации и откликам.
- Порядок каталога по умолчанию: рейтинг по убыванию → более ранняя публикация → идентификатор. Можно выбрать сначала новые или сначала старые задачи. Фильтры и сортировка меняют представление.
- Предложений может быть сколько угодно. Статусы: `pending`, `selected`, `rejected`. Выбор одной команды не отклоняет остальные; можно выбрать несколько команд.
- Отклик и выбор команды дают 0 баллов. Только подтверждение первого результата бизнесом даёт **10 баллов один раз для пары «задача — команда»**, даже при нескольких предложениях одной команды.
- Готовность показывает полноту задачи. Формула не проверяет истинность текста, репутацию компании или качество обещанного решения.

## AI и локальный режим

Без ключа помощник выбирает пять разных вопросов по исходному описанию и уже заполненной карточке. Явно названные сведения учитываются при выборе вопросов; поля автоматически не заполняются. Если данные названы, но доступ неизвестен, помощник спрашивает о доступе. Для полной карточки он предлагает уточнения. Ответы остаются редактируемыми.

Для OpenAI скопируйте `.env.example` в `.env.local`, укажите серверный ключ и перезапустите приложение:

| Переменная | Значение по умолчанию |
| --- | --- |
| `AI_MODE` | `auto`; `local` принудительно включает локальные вопросы |
| `OPENAI_API_KEY` | Пусто; без ключа работает локальный режим |
| `OPENAI_MODEL` | `gpt-4.1-mini-2025-04-14` |
| `DATABASE_PATH` | `data/praktika.sqlite` |

Сервер использует Responses API, Structured Outputs, тайм-аут 20 секунд, `maxRetries: 0` и `store: false`. Извлечённые значения принимаются только при проверенном дословном совпадении с фрагментом текста пользователя и только в пустые поля. Повторяющиеся вопросы заменяются неповторяющимися локальными. Некорректный ответ, отказ или ошибка API включают явно обозначенный локальный режим. Ошибка запроса сохраняет текущий ввод в форме. Перед внешним анализом форма предупреждает о передаче текста; сервер ограничивает тело POST 65 000 байтами и AI-анализ 20 запросами в минуту на клиента в памяти процесса.

Ключ находится только в серверном окружении. `.env.local` игнорируется Git; в `.env.example` ключ пустой. AI не публикует задачи и не выбирает команды. [Промпт, схемы, резерв и примеры](docs/AI_PROMPT.md). Проверка реального OpenAI-вызова выполняется отдельно от автоматических тестов, где SDK подменён; её текущий результат приведён в разделе проверок ниже.

## Стек и структура

Сохранён существующий стек: **Next.js App Router, React, TypeScript, Tailwind CSS, Zod и SQLite через `node:sqlite`**. Один Node.js процесс, без ORM. Vitest проверяет правила и серверные операции; Playwright — сценарии в браузере. Локальный шрифт DM Sans, Lucide для вспомогательных иконок, собственные SVG для бренда и иллюстраций. Sharp экспортирует PNG.

Версии из `package-lock.json`: Next.js **16.3.6**, React **19.3.0**, TypeScript **6.0.3**, Tailwind CSS **4.3.3**, Zod **4.6.5**, OpenAI SDK **7.23.0**, Vitest **5.0.1**, Playwright **1.63.0**. `npm ci` устанавливает именно lockfile.


[Архитектура и HTTP-контракт](docs/ARCHITECTURE.md). Устаревшие дизайн-документы не являются требованиями текущей версии.

## SVG и воспроизводимый экспорт PNG

```sh
npm run assets:export
```

Скрипт читает все `.svg` из `src/assets/svg/`, проверяет `viewBox` и отсутствие встроенного растра/внешних изображений, копирует SVG в `public/assets/svg/` и экспортирует каждый через Sharp в `public/assets/png/<имя>@1x.png` и `<имя>@2x.png`. Для hero дополнительно создаётся `hero-preview.png` на светлом фоне. Иконки имеют базовый размер 24×24, логомарк — 40×40, hero — 680×490. Перед экспортом цвет `currentColor` заменяется на брендовый тёмный `#16332f`.

В набор входят логотип, логомарк, навигация, действия, шесть категорий, пустое состояние и редакционная иллюстрация бизнеса со студентами. Все изображения локальные. Изображения из внешних сервисов и hotlinking не используются.

## Демоданные и ограничения

Аудит текущей кодовой базы и план исправлений находятся в [AUDIT.md](AUDIT.md) и [PLAN.md](PLAN.md). При сбое обновления после успешного сохранения интерфейс отдельно сообщает, что действие сохранено, и предлагает **«Обновить данные»**. Повторять отправку формы не требуется. При смене роли предыдущий снимок очищается; ответы от прежней роли не применяются.

При первой инициализации SQLite содержит **пять неопубликованных черновиков**, **пять опубликованных карточек** с рейтингами **100 / 90 / 75 / 55 / 20**, **пять команд** и **пять предложений**. Черновики содержат тему и исходное описание, имеют отдельные стабильные ID, `confirmed_at = NULL`, `published_at = NULL` и официальный рейтинг 0. Они доступны бизнесу и скрыты от команд и каталога. Эти же пять описаний доступны как примеры в конструкторе. `INSERT OR IGNORE` сохраняет пользовательские правки при повторном запуске.

ID черновиков: `draft-coffee`, `draft-education`, `draft-delivery`, `draft-inventory`, `draft-marketing`. Количество и исходные рейтинги относятся к свежей базе: редактирование и публикация пользователем закономерно меняют её состояние.

Данные синтетические: кофейня, образование, доставка, склад и отзывы клиентов. Прототипы и контакты используют демонстрационные адреса `example.com`; ссылки не подтверждают существование готового прототипа. Внешних наборов данных нет. OpenAI — единственный необязательный внешний сервис анализа; NVIDIA-интеграция в этот MVP не добавлена.

Один демобизнес управляет всеми задачами. `x-demo-actor` моделирует роль, но не является аутентификацией. Профиль восстанавливается после перезагрузки в той же вкладке; несохранённый редактор сбрасывается. Сохранённые данные остаются в SQLite, избранное — в браузере. Выбор/отклонение предложения окончательны для этого предложения; подтверждённый первый результат не редактируется.

Подборки основаны на точных совпадениях темы и навыков и объясняют совпадения. Чата, уведомлений, загрузки файлов, календаря и production-инфраструктуры нет. SQLite рассчитана на один локальный сервер. Демороли можно переключать без проверки личности: приложение предназначено для локальной оценки, публичная эксплуатация требует настоящей аутентификации и разделения владельцев. Публичная deployed-версия не заявляется.

## Как проверить требования кейса

Матрица связывает правило с наблюдаемым действием и исходником проверки. Наличие теста само по себе не означает, что он прошёл: результаты запуска приведены выше.

| Требование | Действие в приложении / ожидаемый результат | Проверка |
| --- | --- | --- |
| Слабое описание → минимум 3 уместных вопроса | `/tasks/new`: сравнить кофейню и описание курьеров; вопросы учитывают текст и ответы | `tests/ai-readiness.test.ts`, `tests/ai.test.ts` |
| Редактируемая полная карточка и подтверждение | Дополнить поля, открыть предпросмотр, подтвердить; правка сбрасывает подтверждение | `tests/e2e/builder.spec.ts`, `tests/e2e/demo.spec.ts` |
| Объяснимый рейтинг 0–100 и границы уровней | Карточка показывает девять критериев; данные и метрика требуют обе части | `tests/readiness.test.ts` |
| Публичны только подтверждённые изменения | Изменить опубликованную задачу и уйти без подтверждения: публичные данные прежние | `tests/store.test.ts`, `tests/e2e/demo.spec.ts` |
| Открытый каталог и низкая готовность | Каждая команда видит все публикации; задача с низким рейтингом принимает отклик | `tests/catalog.test.ts`, `tests/store.test.ts`, `tests/e2e/builder.spec.ts` |
| Неограниченные отклики, ручной выбор нескольких команд | Отправить несколько предложений, выбрать два, отклонить третье; статусы независимы | `tests/store.test.ts`, `tests/e2e/proposals.spec.ts` |
| Первый результат: 10 баллов один раз | Подтвердить результат; повторный запрос и два предложения одной команды не дают вторую награду | `tests/store.test.ts`, `tests/e2e/proposals.spec.ts` |
| 5 черновиков + 5 карточек + 5 команд + 5 предложений | Свежая SQLite: бизнес видит черновики, команды — только публикации; перезапуск сохраняет правки | `tests/store.test.ts`, `tests/e2e/builder.spec.ts` |
| AI без выдуманных значений и явный резерв | Подтверждение дословного источника; без ключа/при отказе — локальные вопросы, ввод сохраняется | `tests/ai.test.ts`, `tests/ai-fallback.test.ts`, `tests/e2e/builder.spec.ts` |
| Надёжность входов и деморолей | Неверный JSON, поля, URL и чужие действия отклоняются; большое тело ограничено; клиентский score игнорируется | `tests/http.test.ts`, `tests/store.test.ts`, `tests/ai.test.ts` |
| Полный путь и сохранность SQLite | Описание → публикация → предложение → выбор → результат → +10; повторить после остановки сервера | `tests/e2e/demo.spec.ts`, `tests/store.test.ts`, `npm run test:production`, [ручной сценарий](docs/DEMO.md) |

`npm test` запускает все Vitest-проверки из матрицы, `npm run test:e2e` — браузерные. Точечно: `npx vitest run tests/readiness.test.ts` или `npm run test:e2e -- tests/e2e/demo.spec.ts`.
