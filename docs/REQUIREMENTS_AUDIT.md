# Проверка требований AI Sana / HackAlem

Проверка кода и адресные тесты выполнены 23 сентября 2026 года. Это карта доказательств, а не прогноз балла жюри. Устаревшие дизайн-документы не использованы как требования.

## Применимые источники

- [Кейс AI Sana](https://docs.google.com/document/d/1lFWekP2SirFarATKkWa5neHNL5DlhjZKkUacvGyZk8k/edit): обязательный пользовательский путь, поля, правила каталога, AI и синтетические данные. При проверке прочитан текст экспорта документа.
- `Правила оценивания.docx`: технический отбор — соответствие 20, код 25, документация 20, воспроизводимость 20, надёжность 15. Demo Day — ценность 25, результат 20, инновационность 15, развитие 20, показ и ответы 20.
- `HACKALEM_STRUCTURE.md`: локально сохранённый организационный контекст; официальный репозиторий, фактические почасовые результаты и сдача до 18:00 требуют отдельного подтверждения на платформе.
- Инструкция участника, предоставленная пользователем: один кейс, использование AI-агента, GitHub, README и форма «Сдать решение».

Шкала внутри кейса (20/15/25/15/10/10/5) и техническая шкала DOCX различаются. Ни одну из них нельзя выдавать за внутреннюю методику AI-бота: такая методика в проверенных материалах отсутствует. Рейтинг задачи 0–100 в приложении не является оценкой проекта.

## Адресная проверка надёжности

Добавлены и выполнены **5 тестов** в `tests/http.test.ts`. Они вызывают настоящие HTTP-обработчики с `Request`, используют отдельную SQLite в памяти и не вызывают внешний AI:

```sh
npx vitest run tests/http.test.ts tests/ai.test.ts tests/ai-readiness.test.ts
```

Результат этого запуска: 18 тестов в 3 файлах прошли. Проверены:

- неправильный JSON: `/api/demo` возвращает 400, `/api/analyze` — 422;
- тело 65 001 байт: оба обработчика возвращают 413; поток без надёжного `Content-Length` отдельно проверен в `tests/ai.test.ts`;
- ссылка `javascript:` — 422; неизвестный профиль и действия команды от имени бизнеса — 403;
- команда видит только свои предложения; неопубликованная задача скрыта от команд и не принимает отклик;
- клиентские `score: 100` и `readiness.score: 100` не меняют рассчитанный сервером нулевой рейтинг;
- чужая невыбранная команда не сдаёт результат и не подтверждает награду;
- два выбранных предложения одной команды дают один результат; два подтверждения оставляют ровно 10 баллов;
- уместность вопросов для явно названных данных и отсутствующего доступа, а также отклонение служебных enum как источников AI-извлечения.

Отдельно ранее прошли `tests/ai-fallback.test.ts`: неправильный ответ модели, отсутствие ключа и ошибка/тайм-аут включают локальный резерв.

Проверка отслеживаемых файлов не выявила совпадений с локальным API-ключом или токенов стандартного формата. `.env.local` игнорируется Git; SQLite-файлы не отслеживаются. Поиск токенов в истории Git также не дал совпадений. Значения секретов в отчёт не выводились. Такой поиск не является универсальным доказательством отсутствия всех возможных секретов.

`npm run test:production` прошёл в отдельной чистой копии проекта. Скрипт `scripts/verify-production.mjs` запускает настоящий production-сервер без ключа, использует новую временную базу, проходит создание → предложение → выбор → результат → подтверждение, перезапускает процесс и сравнивает весь снимок сохранённых данных. Повторное подтверждение после перезапуска не меняет ни снимок, ни 10 баллов. Рабочая база не используется.

## Границы подтверждения

- `x-demo-actor` — открытый переключатель демонстрационной роли. Это не аутентификация: один демобизнес управляет всеми задачами. Полноценные аккаунты и производственная инфраструктура исключены из обязательного MVP кейсом.
- Ограничение AI-запросов хранится в памяти процесса; входные IP-заголовки подходят для локального демо, но без доверенного прокси не дают защиты публичного сервиса.
- Рейтинг проверяет заполненность подтверждённых полей. Он не доказывает истинность текста или достижение бизнес-эффекта.
- Реальный OpenAI-вызов, чистый запуск, перезапуск процесса, браузерный прогон и фактическая сдача проверяются отдельно. Их итоговый статус следует читать в README и `docs/progress.md`; наличие тестового файла само по себе не подтверждает успешный запуск.
- Численность команды, личное присутствие, активацию организаторских доступов и отправку формы нельзя подтвердить чтением кода. История коммитов должна отражать фактическую работу; задним числом результаты не создаются.
